    Session lifecycle

    A session is one sandbox, one harness and one workspace, alive across many turns. The supervisor's reconcile loop drives every transition from the database. Every terminal write is a conditional update, so it happens exactly once. Fire events on the right to walk through the state machine.

    Turns one prompt → one harness process → one result

    Turn states: queued → running → complete | failed | stopped | limit_exceeded. The result file the in-sandbox runner writes is authoritative, not stdout. An EXIT trap writes failed if the harness didn't. A reply ending in TERRARIUM_OUTCOME: failed - <reason> makes the turn failed.

    Blast radius of a compromised agent

    Core assumption: everything inside a sandbox is attacker-controlled. Task text, repository content, dependencies, tool output and model output are data, never authority. A prompt-injected agent is treated as an attacker with a shell as uid 1000 in the sandbox. This is what that attacker can reach.
